# Address Book — REST API (FastAPI)

A REST API for managing contacts with Indonesian data conventions (RT/RW, kelurahan,
kecamatan, NIK), built with **FastAPI**, **SQLAlchemy** and **PostgreSQL**, and packaged
with **Docker**.

It is the backend for the React front end:
[defianto/AddressBook-React](https://github.com/defianto/AddressBook-React).

## Features

- **Contacts CRUD** with pagination, filters (group, city, favourite) and keyword search
  across name, alias, email, phone, WhatsApp, company and city
- **Partial updates**: `PUT /contacts/{id}` only changes the fields that are sent
- **Reference data** endpoints for religion, gender and marital status
- **User management**: create, edit, activate/deactivate, change password, delete
- **Password hashing** with bcrypt plus a server-side **pepper** kept outside the database
- Interactive API docs (Swagger UI and ReDoc) generated by FastAPI
- Runs in Docker with secrets supplied at runtime from `.env`

## Tech stack

- Python 3.12, FastAPI, Uvicorn
- SQLAlchemy 2, PostgreSQL (psycopg2)
- Pydantic 2 for request/response validation
- passlib + bcrypt
- Docker / Docker Compose

## API overview

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/auth/login` | Check username and password, return the user |
| `GET` | `/contacts` | List contacts (`page`, `page_size`, `grup`, `kota`, `is_favorite`) |
| `GET` | `/contacts/search?q=` | Keyword search |
| `GET` | `/contacts/favorites` | Favourite contacts |
| `GET` | `/contacts/{id}` | Contact details |
| `POST` | `/contacts` | Create a contact |
| `PUT` | `/contacts/{id}` | Partially update a contact |
| `DELETE` | `/contacts/{id}` | Delete a contact |
| `GET` | `/ref/agama` · `/ref/jenis-kelamin` · `/ref/status-perkawinan` | Reference data |
| `GET` `POST` `PUT` `DELETE` | `/users`, `/users/{id}` | User management |
| `POST` | `/users/{id}/change-password` · `/users/{id}/toggle-aktif` | User actions |
| `GET` | `/health` | Health check |

Paginated responses look like `{ "total": 42, "page": 1, "page_size": 20, "data": [ ... ] }`.

Full, interactive documentation is available at `/docs` (Swagger UI) and `/redoc` once the API is running.

## Getting started

### 1. Database

Create the schema in PostgreSQL with [`db/schema.sql`](db/schema.sql) (tables, reference
data, triggers and one sample contact):

```bash
psql -U <user> -f db/schema.sql
```

### 2. Configuration

```bash
cp .env.example .env
```

Edit `.env`:

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string, e.g. `postgresql://user:password@host.docker.internal:5432/address_book` |
| `PASSWORD_PEPPER` | Long random secret appended to passwords before hashing. Changing it invalidates every existing password. |

### 3. Run with Docker

```bash
docker compose up -d --build
```

The API listens on http://localhost:8000. Open http://localhost:8000/docs to try it.

### 4. Create the first admin user

Password hashes depend on `PASSWORD_PEPPER`, so generate them with the same `.env`:

```bash
pip install bcrypt python-dotenv
python reset_password.py
```

The script prints a bcrypt hash. Insert the user with it:

```sql
INSERT INTO app_user (username, password, nama_lengkap, role)
VALUES ('admin', '<hash from the script>', 'Administrator', 'ADMIN');
```

### Run without Docker (development)

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

## Project structure

```
main.py                 # FastAPI app, CORS, router registration
app/
├── database.py         # SQLAlchemy engine and session
├── models.py           # ORM models (address_book, app_user, reference tables)
├── schemas.py          # Pydantic request/response models
├── crud.py             # database queries
├── security.py         # bcrypt + pepper hashing
└── routers/            # auth, contacts, references, users
db/schema.sql           # PostgreSQL schema
reset_password.py       # CLI to generate a password hash
Dockerfile
docker-compose.yml
```

## Security notes and roadmap

This project is a learning and portfolio project. Before using it outside a trusted network:

- **Add token-based authentication.** `/auth/login` verifies credentials but does not issue
  a token yet, so the other endpoints are not protected. Planned: JWT with role checks
  (ADMIN vs USER).
- **Restrict CORS.** `main.py` currently allows every origin.
- Keep `.env` out of version control and out of Docker images (handled by `.gitignore`
  and `.dockerignore`).
